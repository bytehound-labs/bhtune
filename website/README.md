# BHTune documentation site

The [Docusaurus](https://docusaurus.io/) app that publishes [`../docs`](../docs) as a browsable,
searchable website. See the repository root [`README.md`](../README.md) and
[`AGENTS.md`](../AGENTS.md) for the overall project — this file only covers this package.

The Markdown content itself is **not** stored here. `docusaurus.config.ts` points its `docs`
plugin at the real repo-root `docs/` folder (`path: '../docs'`), so that folder stays the single
source of truth for both this site and anyone reading it directly on GitHub — a doc change and
the code change it documents land in the same commit. `docs/internal/` is excluded from the
build; everything else in `docs/` is published. See "Documentation system" in `AGENTS.md` for
the full design (the three content tiers, the versioning plan, and the AI docs agent).

## Development

```sh
pnpm install    # from the repo root — this is a pnpm workspace
cd website
pnpm start      # dev server on http://localhost:3000, hot-reloading
```

Editing any file under `../docs` while `pnpm start` is running reloads instantly, the same as
editing a file inside `website/` itself.

## Build

```sh
pnpm run build
```

Produces static files in `build/`. This is also a drift gate, not just a packaging step:
`onBrokenLinks`/`onBrokenAnchors` are both set to `'throw'`, so a Markdown link or heading
anchor that no longer resolves fails the build instead of shipping a dead link. CI runs this on
every PR.

## Scripts

| Command                 | Purpose                                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| `pnpm start`            | Dev server with hot reload.                                                              |
| `pnpm run build`        | Type-check, build the static site into `build/`, and enforce the link/anchor drift gate. |
| `pnpm run serve`        | Serve an already-built `build/` directory locally.                                       |
| `pnpm run typecheck`    | Type-check only (`tsc`), no build.                                                       |
| `pnpm run lint`         | Lint with [oxlint](https://oxc.rs/).                                                     |
| `pnpm run format:check` | Check formatting with Prettier (`pnpm exec prettier --write .` to fix).                  |

## Adding or reordering pages

Sidebar structure and ordering come from `docs/`'s own folder layout, `_category_.json` files,
and per-page `sidebar_position`/`slug` frontmatter — not from anything in `website/`. To add a
new guide, add a Markdown file under `docs/guides/`; to change where it sits in the sidebar, set
`sidebar_position` in its frontmatter. `sidebars.ts` in this package only wires up the
autogenerated-from-filesystem sidebar; it doesn't need to change for routine content edits.

## Deployment

Intended for GitHub Pages (`bytehound-labs.github.io/bhtune`) via `actions/deploy-pages`, per
`docs-site-deploy` in `AGENTS.md`'s roadmap — not yet wired into CI. Until then, `pnpm run
build` + `pnpm run serve` is how to preview the site locally.
